Guia Prático de Git e GitHub

Do primeiro commit ao portfólio publicado: o que foi praticado ao longo do curso, em um só lugar.

1. Ciclo de vida local

Todo arquivo passa por estados: não rastreado, modificado, preparado (staged) e commitado.

  • git init cria o repositório e git status mostra o estado atual.
  • git add prepara as mudanças e git commit grava o snapshot.
  • .gitignore evita versionar logs, pastas de editor e arquivos locais.
  • Mensagens seguem o padrão Conventional Commits, como feat:, fix: e docs:.

2. Desfazendo erros

  • git restore descarta alterações ainda não commitadas.
  • git commit --amend corrige a mensagem do último commit, ainda não publicado.
  • git revert neutraliza um commit criando um novo, o que é seguro para histórico compartilhado.

3. Branches, merge e rebase

  • Uma branch é um ponteiro leve para um commit, e git switch -c cria e muda de branch.
  • git merge une históricos e, se duas branches mexem na mesma linha, o conflito é resolvido à mão.
  • git rebase reaplica commits sobre uma nova base e só deve ser usado em commits locais.

4. Trabalho em equipe

  • No GitHub Flow, cada mudança nasce de uma Issue, vira branch, passa por Pull Request e Code Review.
  • Closes #N na descrição do PR fecha a Issue automaticamente no merge.
  • Comentários de review são classificados como Sugestão, Bloqueador ou Opcional.

5. GitHub Pages

Um repositório público com index.html na raiz vira um site, ativado em Settings, Pages.
